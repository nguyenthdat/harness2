# Native Rust Reverse Engineering

Actionable guidance for reverse engineering compiled Rust binaries (ELF, PE, Mach-O). Covers Rust's memory model, standard library types, panic signatures, demangling schemes, and CFG de-bloating.

---

## 1. Rust Memory Model & Core Types

### Fat Pointers (16 Bytes on 64-bit)
Rust does not use null-terminated strings for native string slices. Many Rust types are fat pointers composed of two 64-bit words:

1. **`&str` (String Slice)**:
   - Layout: `[ ptr: 8 bytes ][ len: 8 bytes ]`.
   - In assembly/pseudocode, passing a string slice requires two registers (e.g., `RDI` = buffer address, `RSI` = byte length in System V AMD64).
   - The buffer in `.rodata` has **no trailing null terminator (`\x00`)**. Consecutive string literals may be packed together.

2. **`&[T]` (Slice)**:
   - Layout: `[ ptr: 8 bytes ][ len: 8 bytes ]`.
   - Length denotes number of elements of type `T`, not byte count.

3. **`&dyn Trait` (Trait Object / Dynamic Dispatch)**:
   - Layout: `[ data_ptr: 8 bytes ][ vtable_ptr: 8 bytes ]`.
   - `vtable_ptr` points to a static structure generated by `rustc`:
     ```c
     struct TraitVTable {
         void (*destructor)(void*); // Drop in place
         size_t size;               // Size of concrete type
         size_t align;              // Alignment of concrete type
         void (*methods[])();       // Trait methods
     };
     ```

4. **`String` & `Vec<T>` (24 Bytes on 64-bit)**:
   - Layout: `[ ptr: 8 bytes ][ cap: 8 bytes ][ len: 8 bytes ]` (or `[ ptr ][ len ][ cap ]` depending on rustc version).
   - Heap-allocated buffer managed by global allocator (jemalloc or system malloc).

## 2. Enums, `Option<T>`, `Result<T, E>` & Niche Optimization

### Discriminant Tags
- Standard Rust enum with data:
  ```text
  Offset +0x00: [ Discriminant Tag (1, 2, 4, or 8 bytes) ]
  Offset +0x08: [ Payload Union (sized to largest variant) ]
  ```
- In disassembly, a `match` expression appears as a comparison or jump table on the discriminant value (`0`, `1`, `2`, ...).

### Niche Optimization (Zero-Cost `Option`)
When an inner type has an invalid bit pattern (a "niche"), `rustc` uses that invalid pattern to represent other variants without allocating an extra discriminant byte:
- **`Option<&T>` or `Option<Box<T>>`**:
  - Pointer must never be `0` (null).
  - `Some(ptr)` -> `ptr != 0`.
  - `None` -> `ptr == 0` (`NULL`).
  - Total size: 8 bytes (identical to raw pointer).
- **`Option<bool>`**:
  - `bool` only uses `0` (`false`) and `1` (`true`).
  - Values `2..=255` are niches. `None` is typically represented by `2`.
  - Total size: 1 byte.
- **`Result<T, E>`**:
  - If either `T` or `E` contains a niche, the entire `Result` can often fit without an extra tag byte.

## 3. Panic Mechanisms & Signatures

### Panic Entry Points
Rust binaries contain distinctive panic handlers in `core` and `std`:
- `core::panicking::panic`
- `core::panicking::panic_fmt`
- `core::panicking::panic_bounds_check` (triggered on slice index out of bounds)
- `rust_begin_unwind`
- `rust_eh_personality` (exception handling personality routine for landing pads)

### Panic String Structure
Rust panic sites in `.rodata` reference structured file/line metadata:
```c
struct PanicLocation {
    const char* filename_ptr;
    size_t      filename_len;
    uint32_t    line;
    uint32_t    column;
};
```
- **Triage Strategy**: Searching for strings containing `/rustc/<commit_hash>/library/` or project-specific crate source paths (e.g., `src/main.rs`, `src/crypto.rs`) immediately pinpoints source filenames and line numbers for critical code blocks.

## 4. Symbol Demangling

### Legacy Scheme
- Structure: `_ZN<length><path>...<length><name><hash>E`
- Example: `_ZN4core3fmt10ArgumentV13new17h892d4b96d910eb67E`
  - Demangled: `core::fmt::ArgumentV1::new` with hash `h892d4b96d910eb67`.
- Demangle with `c++filt` or `rustfilt`:
  ```bash
  rustfilt _ZN4core3fmt10ArgumentV13new17h892d4b96d910eb67E
  ```

### v0 Scheme (RFC 2603)
- Structure: starts with `_R`. Uses compact base62 encoding for disambiguators and namespaces.
- Example: `_RNvNtCs1234_4core3str6to_str`
- Requires modern demanglers:
  ```bash
  rustfilt _RNvNtCs1234_4core3str6to_str
  ```

## 5. Decompilation Triaging & Inlining De-bloat

Rust compilers make heavy use of monomorphization and inlining, generating massive, repetitive Control Flow Graphs (CFGs).

### 1. Prune Cold Panic Branches
- Look at function control flow: almost every checked arithmetic operation, array access, or `unwrap()` generates a conditional branch:
  - **Happy path**: falls through to continuation.
  - **Cold path**: loads a `PanicLocation` structure, calls `core::panicking::panic_bounds_check`, and jumps to an unreachable instruction (`ud2` on x86-64).
- In IDA/Ghidra pseudocode, fold or ignore blocks calling `panic_*` functions to reveal the original business logic.

### 2. Identify Drop Glue & Landing Pads
- When an object goes out of scope or unwinds during a panic, cleanup code runs:
  - Function: `core::ptr::drop_in_place<Type>`
  - Look for sequences calling drop glue on local stack slots followed by `_Unwind_Resume`.

### 3. Iterators vs Loops
- Rust iterators (`.iter().filter().map().collect()`) are often unrolled or compiled into tight pointer increment loops. What looked like 5 functional method calls in source is a single loop with `cmp`, `lea`, and pointer arithmetic in assembly.

## 6. Cargo Auditable Dependency Extraction

Rust binaries compiled with `cargo-auditable` embed dependency package metadata in a dedicated section:
- ELF: `.dep-v0`
- Mach-O: `__DATA,.dep-v0`
- PE: `.dep-v0`

### Tool Inspection via REA MCP
Use `inspect_rust_binary` to recover all bundled crate names, exact versions, and dependency graphs without a disassembler:
```json
{
  "path": "/path/to/binary",
  "detail": "summary"
}
```
For selected packages:
```json
{
  "path": "/path/to/binary",
  "view": {
    "collection": "packages",
    "names": ["tokio", "serde", "ring"],
    "fields": ["name", "version", "source"]
  }
}
```
